# 🚀 AWS Lightsail Deployment Plan

## Overview
This plan covers deploying the GNET School Management System on **AWS Lightsail** with full automation:
- **GitHub push** → **Docker Hub auto-build** → **Lightsail auto-deploy**
- Zero manual steps after initial setup
- Production-ready configuration for database, security, scaling, and reliability

## 3. GitHub Actions Workflow

Create `.github/workflows/deploy.yml` (already exists at `.github/workflows/deploy.yml` but needs updates):

```yaml
name: Build, Test & Deploy to Lightsail

on:
  push:
    branches: ["main"]
  workflow_dispatch:

env:
  PROJECT_ID: your-gar-project-id  # Optional: GAR if using GCP Artifact Registry
  GAR_LOCATION: us-central1         # Optional fallback

jobs:
  test-and-build:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm run test:online-exam && npm run test:exam-paper

      - name: Verify TypeScript
        run: npx tsc --noEmit

  build-and-deploy:
    needs: test-and-build
    runs-on: ubuntu-latest
    timeout-minutes: 45
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Docker Buildx
        uses: docker-buildx-action@v3

      - name: Login to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_PASSWORD }}

      # --- Build & Push all services ---
      - name: Build and push identity
        uses: docker/build-push-action@v5
        with:
          context: ./services/identity
          file: ./services/identity/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-identity:latest

      - name: Build and push lifecycle
        uses: docker/build-push-action@v5
        with:
          context: ./services/lifecycle
          file: ./services/lifecycle/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-lifecycle:latest

      - name: Build and push staff
        uses: docker/build-push-action@v5
        with:
          context: ./services/staff
          file: ./services/staff/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-staff:latest

      - name: Build and push classroom
        uses: docker/build-push-action@v5

          file: ./services/academic/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-academic:latest

      - name: Build and push finance
        uses: docker/build-push-action@v5
        with:
          context: ./services/finance
          file: ./services/finance/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-finance:latest

      - name: Build and push comms
        uses: docker/build-push-action@v5
        with:
          context: ./services/comms
          file: ./services/comms/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-comms:latest

      - name: Build and push campus
        uses: docker/build-push-action@v5
        with:
          context: ./services/campus
          file: ./services/campus/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-campus:latest

      - name: Build and push api-gateway
        uses: docker/build-push-action@v5
        with:
          context: ./services/gateway
          file: ./services/gateway/Dockerfile
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-api-gateway:latest

      - name: Build and push frontend-spa
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile.frontend
          push: true
          tags: ${{ secrets.DOCKERHUB_USERNAME }}/gnet-sms-frontend-spa:latest

      # --- Deploy to Lightsail ---
      - name: Deploy to Lightsail
        uses: aws-actions/amazon-lightsail-deploy-image@v1
        with:
          aws_access_key_id: ${{ secrets.AWS_ACCESS_KEY_ID }}
```

## 4. Lightsail Initial Setup (One-time)

### Step 1: Create Lightsail Instance
1. Go to [AWS Lightsail](https://aws.amazon.com/lightsail/)
2. Click **"Create instance"**
3. Choose:
   - **Blueprint**: Linux/Unix (OS only)
   - **Instance plan**: $5/month (or $10 for more memory/CPU)
   - **Instance name**: `gnet-sms`
   - **Availability zone**: auto-select
4. Click **"Create instance"**

### Step 2: Connect via SSH
```bash
# From your local machine
ssh -i ~/.ssh/your-key.pem lightsail-user@your-lightsail-instance-name.lightsaillightsaillink.com
```

### Step 3: Install Docker & Docker Compose
```bash
# Update and install Docker
sudo apt-get update
sudo apt-get install -y docker.io docker-compose v2-plugin

# Start and enable Docker
sudo systemctl start docker
sudo systemctl enable docker

# Add user to docker group (log out/in after)
sudo usermod -aG docker $USER
newgrp docker
```

### Step 4: Create Docker Compose File
Create `docker-compose.yml` on the Lightsail instance (or deploy via GitHub Actions):

```yaml
version: "3.9"

services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: sms
      POSTGRES_PASSWORD: sms
      POSTGRES_DB: sms_db
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U sms -d sms_db"]
      interval: 5s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 5s
      retries: 10

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: smsminio
      MINIO_ROOT_PASSWORD: smsminio-secret
      MINIO_API_CORS_ALLOW_ORIGIN: "*"
    ports: ["9000:9000", "9001:9001"]
    volumes: - miniodata:/data
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 10s
      timeout: 5s
      retries: 5

  # Multi-service app (Lightsail uses a simplified setup)
  app:
    image: your-dockerhub-id/gnet-sms:latest
    environment:
      NODE_ENV: production
      DATABASE_URL: postgresql://sms:sms@postgres:5432/sms_db?schema=public
      # ... other env vars from GitHub secrets
    ports: ["80:80", "3000:3000", "8081:8081"]
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      minio:
        condition: service_healthy
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:
  miniodata:
```

### Step 5: Start Services
```bash
# From the directory with docker-compose.yml
docker compose up -d
```

## 6. Database Backup & Restore

### 6.1 Automated Backups

**⚠️ Important**: A GitHub-hosted Actions runner cannot directly back up a Docker volume that exists only on the Lightsail server. Use one of two options:

#### Option A: GitHub Actions with SSH (runs backup on production server)

Create `.github/workflows/backup.yml` - this is the updated workflow that connects to the production Lightsail server via SSH and runs `pg_dump` and `mc` inside the actual Docker network:

See `.github/workflows/backup.yml` in the repository for the complete updated workflow that:
- Connects to Lightsail via SSH using `LIGHTSAIL_SSH_KEY` secret
- Runs `pg_dump -U sms -d sms_db` inside the production Docker network
- Backs up MinIO buckets using `mc` inside the production network
- Encrypts backups with GPG and uploads to AWS S3 (separate from production Lightsail)
- Verifies backup integrity
- Retains last 7 daily encrypted backups

#### Option B: Cron on Lightsail instance

Run a daily cron job on the Lightsail Linux VM itself:
```bash
# In crontab (run: crontab -e)
0 2 * * * /usr/local/bin/backup-script.sh
```

### 6.2 Manual Backup from Lightsail SSH
```bash
# Create backup (runs inside Docker network)
docker compose exec postgres pg_dump -U sms -d sms_db > backup_$(date +%F).sql

# List backups
ls -la backup_*.sql

# Download from Lightsail (SCP from local machine)
scp -i ~/.ssh/lightsail-key.pem sms-user@lightsail-instance:~/backup_2026-01-15.sql ./backups/
```

### 6.2 Manual Backup from Lightsail SSH
```bash
# Create backup
pg_dump -U sms -d sms_db > backup_$(date +%F).sql

# List backups
ls -la backup_*.sql

# Restore from backup
docker compose exec postgres psql -U sms -d sms_restore < backup_2026-01-15.sql
```

### 6.3 Backup Retention
- Keep 7 daily backups
- Keep 4 weekly backups (rename with week number)
- Keep 3 monthly backups
- Use S3 lifecycle policies for automatic expiration

## 7. Security Best Practices

### 7.1 Secrets Management
- **Never** hardcode secrets in Dockerfiles or compose files
- Use **GitHub Secrets** for CI/CD
- Use **Lightsail environment variables** or **AWS Secrets Manager** for runtime secrets
- Rotate JWT secrets every 90 days

### 7.2 Network Security
- Lightsail firewall: Only open ports 80 (HTTP), 443 (HTTPS), 22 (SSH)
- Internal service ports (3011-3018) are only accessible within the docker network
- Use **MinIO CORS** configuration for browser uploads
- Enable **HTTPS** via Let's Encrypt (see Step 8)

### 7.3 Container Security
- Run services as non-root users (already in Dockerfiles)
- Use `readonly` filesystem where possible
- Alpine Linux base images (smaller attack surface)
- Regularly update base images: `docker compose pull`

### 7.4 PostgreSQL Security
- Use strong passwords (already in compose)
- Enable `pg_hba.conf` restrictions if needed
- Set `max_connections` appropriately for Lightsail
- Use prepared statements to prevent SQL injection (app-level)

### 7.5 Race Condition Prevention
- **Prisma transactions** already used for critical operations
- **Database row-level locking** via `SELECT ... FOR UPDATE` where needed
- **Idempotency keys** on create operations (already in admission service)
- **Optimistic concurrency** via Prisma's `_version` field
- **Health check endpoints** prevent request routing to dead containers

## 9. Scaling Considerations

### 9.1 Vertical Scaling (Lightsail)
- Upgrade instance plan: $5 → $10 → $20 → $40/month
- More RAM/CPU available instantly
- No downtime when upgrading

### 9.2 Horizontal Scaling (Advanced)
- Deploy multiple Lightsail instances behind **AWS ALB (Application Load Balancer)**
- Use **EFS** for shared storage (MinIO + PostgreSQL)
- Sticky sessions required for session affinity
- **Not recommended for initial deployment** - start vertical

### 9.3 Resource Limits
Set Docker resource limits in `docker-compose.yml`:

```yaml
services:
  app:
    deploy:
      resources:
        limits:
          cpus: '2.0'
          memory: 2G
        reservations:
          cpus: '0.5'
          memory: 1G
```

## 10. Auto-Restart & High Availability

### 10.1 Docker Restart Policy
All services should have `restart: unless-stopped` in compose:

```yaml
services:
  postgres:
    restart: unless-stopped
  app:
    restart: unless-stopped
```

### 10.2 Lightsail Instance Auto-Start
- In Lightsail console, go to **Instance settings**
- Enable **"Auto-start on schedule"** if needed
- Or use AWS CLI: `aws lightsail enable-instance-auto-start`

### 10.3 Health Checks
All services have health checks defined:
- PostgreSQL: `pg_isready`
- Redis: `redis-cli ping`
- MinIO: HTTP health endpoint
- App: Custom `/health/live` endpoint (defined in Dockerfiles)

### 10.4 Deployment Strategy
**Blue-Green Deployment** (via GitHub Actions):
1. New deployment pulls `gnet-sms:latest`
2. Lightsail deploys to new container
3. Health check verifies success
4. Traffic switches to new version
5. Old version can be kept as rollback

**Rollback**: If new deployment fails health check, previous version remains running.

## 11. Race Condition Safeguards

### 11.1 Database-Level Prevention
```sql
-- Example: Unique constraint on admission application number
CREATE UNIQUE INDEX idx_admissions_app_number ON admission_applications(app_number);

-- Example: Advisory locks for critical operations
SELECT pg_advisory_xact_lock(12345) WHERE ...;
```

### 11.2 Application-Level Patterns
- **Prisma transactions** with proper isolation levels
- **Idempotency keys** on POST requests (check `x-idempotency-key` header)
- **Version checking** on updates: `WHERE version = expected_version`
- **Atomic operations** for counters and increments

### 11.3 Concurrency Testing
- Load test with `hey` or `k6`
- Monitor `pg_stat_activity` for long-running queries
- Set `statement_timeout` and `lock_timeout` in PostgreSQL

## 13. Rollback Procedure

### 13.1 Quick Rollback (Docker)
```bash
# List images
docker images | grep gnet-sms

# Run previous version
docker run -d --name app-old \
  -p 80:80 \
  -e NODE_ENV=production \
  -e DATABASE_URL=postgresql://sms:sms@postgres:5432/sms_db?schema=public \
  your-dockerhub-id/gnet-sms:2026-01-01

# Switch traffic (if using port-based routing)
# Or stop new, start old: docker stop app-new && docker start app-old
```

### 13.2 GitHub Actions Rollback
```yaml
# In workflow, set:
DOCKER_TAG: ${{ github.event.before == '' && 'latest' || 'previous-sha' }}
```

### 13.3 Lightsail Rollback
1. SSH to Lightsail instance
2. `docker compose down`
3. `docker compose up -d` (compose remembers previous version if using named images)
4. Or manually: `docker run -d old-image`

## 15. Post-Deployment Verification

After first `docker compose up -d`:

1. **Access the app**: `http://<lightsail-ip>:8080` or `http://<domain>`
2. **Login**: Use default admin credentials or create first user
3. **Check health**: 
   ```bash
   curl http://<lightsail-ip>:3000/health/live
   curl http://<lightsail-ip>:3011/health/live
   ```
4. **Verify services**: PostgreSQL, Redis, MinIO all running
5. **Test critical flow**: Create admission application → upload document → virus scan
6. **Check logs**: `docker compose logs -f` for any errors
7. **Verify backup**: Run manual pg_dump and confirm it works
